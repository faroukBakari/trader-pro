# Skill Design

Governance conventions for the skill-bank architecture at `.claude/`.

---

## Architecture

```
.claude/
  skill-bank/                    ← flat storage, source of truth (never moves)
    {skill-name}/SKILL.md        ← leaf skills (author-maintained)
  skills/                        ← categories only (Skill Tool scans this)
    {category}/SKILL.md          ← auto-generated glossary (DO NOT EDIT)
  scripts/
    build-skill-tree.py          ← glossary generator
```

**Key principle**: Skills never move. Category assignment lives in each skill's `category` frontmatter field. The tree builder reads `category` from skill-bank skills and generates glossaries in `skills/`.

**Re-clustering = regenerate glossaries only.** Zero file moves, zero symlinks.

---

## When to Use This Skill

- **Creating** a new skill — verify naming, frontmatter, category fit
- **Reorganizing** skills into categories — update `category` frontmatter, rebuild
- **Reviewing** skill changes — run quality gates T1-T4
- **Running the tree builder** — regenerate category glossaries
- **Deduplicating** — assess overlap between skills

## Naming Conventions

### Categories

| Rule | Constraint | Example |
|------|-----------|---------|
| Format | `{domain}` noun, kebab-case | `testing`, `prompting`, `ia-design` |
| Length | Max 20 characters | |
| Content | Domain noun only, no verbs | `testing` not `run-tests` |

### Skills

| Rule | Constraint | Example |
|------|-----------|---------|
| Format | `{modifier}-{concept}`, kebab-case | `backend-testing`, `fix-type-errors` |
| Length | Max 30 characters | |
| Uniqueness | Globally unique across all categories | |

### Abbreviation Allowlist

Only these abbreviations are permitted in names: `ia`, `api`, `ws`, `ui`, `ux`, `tv`, `db`, `cli`, `mcp`.

All other terms must be spelled out (`frontend` not `fe`, `backend` not `be`).

## Frontmatter Spec

Every `SKILL.md` must have YAML frontmatter between `---` fences. The opening `---` **must be line 1** — any content before it (HTML comments, blank lines, BOM) prevents the Skill Tool from parsing the file.

### Required Fields

| Field | Type | Constraint |
|-------|------|-----------|
| `name` | string | Must match directory name |
| `description` | string | Max 120 chars. Formula: `"{What} — {trigger phrase}. Use when {contexts}."` |
| `keywords` | list | 3-7 terms, lowercase, no duplicates |
| `category` | string | Category slug matching a glossary in `skills/` (e.g., `testing`, `prompting`) |
| `disable-model-invocation` | bool | Must be `true` for all leaf skills in `skill-bank/` |

**Why both are required**: Without `category`, the skill is orphaned (no glossary lists it). Without `disable-model-invocation: true`, the skill description leaks into the system prompt — bypassing the glossary layer and inflating idle token cost.

### Description Formula

```
"{What it covers}. Use when {trigger context 1}, {trigger context 2}, or {trigger context 3}."
```

- Start with a noun phrase describing coverage
- "Use when" followed by 2-4 concrete trigger contexts
- Must fit 120 characters

### Keywords

- 3-7 terms per skill
- Lowercase, single words or hyphenated compounds
- No overlap >40% with any other skill in same category
- Used by tree builder for keyword index generation

Example:
```yaml
keywords: [testing, pytest, fixtures, mocking, backend]
```

## Category Taxonomy

### Rules

| Rule | Constraint |
|------|-----------|
| Minimum skills | 3 per category (otherwise leave uncategorized) |
| Maximum skills | 12 per category (split if exceeded) |
| Naming | Domain nouns only (see Naming Conventions) |
| Glossary | Auto-generated by `build-skill-tree.py` — never hand-edit |

### Operations

| Operation | When | Procedure |
|-----------|------|-----------|
| **Assign category** | Skill belongs to an existing category | Add `category: {name}` to frontmatter, rebuild |
| **Create category** | 3+ uncategorized skills share a domain | Set `category` on each, rebuild |
| **Merge categories** | Category drops below 3 skills | Update `category` field on affected skills, rebuild |
| **Split category** | Category exceeds 12 skills | Create new category slug, update `category` fields, rebuild |

## Quality Gates

Skills must pass both the existing **S1-S5** gates (from `ia-quality-gates`) and the tree-specific **T1-T4** gates below.

### S1-S5 Reference (from ia-quality-gates)

| Gate | Pass | Fail |
|------|------|------|
| **S1: Agent-Agnostic** | No references to specific agents | References "the implement agent" |
| **S2: Tool-Agnostic** | No tool-specific instructions | Mentions specific tools |
| **S3: Method-Focused** | Step-by-step procedures | Concepts without actionable steps |
| **S4: Portable** | No project-specific paths | References project-specific paths |
| **S5: Progressive Disclosure** | Description in tag; loads on demand | Missing description |

### T1-T6: Tree-Specific Gates

| Gate | Check | Fail Condition | Remediation |
|------|-------|---------------|-------------|
| **T1: Frontmatter Complete** | `name`, `description`, `keywords`, `category`, `disable-model-invocation` all present | Any required field missing | Add missing fields per spec above |
| **T2: Description Formula** | Follows `"{What}. Use when {contexts}."` pattern, max 120 chars | Wrong format or too long | Rewrite to formula |
| **T3: Category Fit** | Skill shares >50% keyword overlap with category siblings | <30% overlap with any sibling | Move to better category or create new one |
| **T4: No Duplication** | <40% keyword overlap with any skill outside category | >40% overlap with another skill | Merge or differentiate |
| **T5: Leaf Hidden** | Leaf skill in `skill-bank/` has `disable-model-invocation: true` | Flag missing or `false` | Add `disable-model-invocation: true` — prevents description leaking into system prompt |
| **T6: Glossary Visible** | Glossary in `skills/` does NOT have `disable-model-invocation: true` | Flag present | Remove the flag — glossaries must be visible for progressive discovery |

## Scripts

### Tree Builder (`build-skill-tree.py`) — regular use

Generates category glossaries from skills that have `category` in frontmatter. **Run after any skill add/remove/re-categorize.**

```bash
# Add a skill:  set `category: {slug}` in its frontmatter, then:
python3 .claude/scripts/build-skill-tree.py --write

# Remove a skill:  delete from skill-bank/, then:
python3 .claude/scripts/build-skill-tree.py --write --clean

# Preview without writing:
python3 .claude/scripts/build-skill-tree.py
```

### What the Tree Builder Generates

Per category, a `skills/{category}/SKILL.md` containing:
- `<!-- AUTO-GENERATED -->` header
- Frontmatter with aggregated description and union of all leaf keywords
- Load instruction pointing to `skill-bank/{name}/SKILL.md`
- Skills table: `| Skill | Description |`
- Keyword index: `| Keyword | Skills |`

Glossaries are **idempotent** — running `--write` multiple times produces identical output.

### Clustering (`cluster-skills.py`) — bulk bootstrap only

Proposes category groupings via TF-IDF + agglomerative clustering. **Not needed for single skill add/remove** — only use when reorganizing all categories from scratch (e.g., after adding 20+ new skills).

```bash
# Preview proposed categories
python3 .claude/skill-bank/skill-design/cluster-skills.py

# Write category field to all skill frontmatters
python3 .claude/skill-bank/skill-design/cluster-skills.py --apply

# Target specific cluster count
python3 .claude/skill-bank/skill-design/cluster-skills.py --target 10 --apply

# Then regenerate glossaries
python3 .claude/scripts/build-skill-tree.py --write --clean
```

## Anti-Patterns

| Anti-Pattern | Why It's Wrong | Fix |
|-------------|---------------|-----|
| 1-2 skill categories | Too few skills to justify a category | Keep uncategorized until 3+ related skills exist |
| Generic keywords | `code`, `development` match everything | Use specific domain terms |
| Hand-editing glossaries | Will be overwritten by tree builder | Edit leaf skills, then rebuild |
| Methodology in glossaries | Glossaries are indexes, not skills | Put methodology in leaf skills |
| Category verbs | `testing` is OK, `run-tests` is not | Use domain nouns |
| Abbreviations outside allowlist | Hurts discoverability | Spell it out |
| Moving skill files for reorganization | Breaks git history, unnecessary churn | Update `category` frontmatter instead |
| Leaf skill missing `disable-model-invocation: true` | Description leaks into system prompt, bypasses glossary layer | Add the flag — all leaf skills must be hidden |
| Leaf skill missing `category` | Skill orphaned from glossaries, invisible to discovery flow | Assign to an existing category or create one (3+ skills) |
| Content before opening `---` frontmatter delimiter | Skill Tool cannot parse frontmatter — skill becomes invisible (not loaded, not listed) | Frontmatter `---` must be the very first line of the file. No HTML comments, blank lines, or BOM before it |
